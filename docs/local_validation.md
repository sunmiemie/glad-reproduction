# 本机验证记录（2026-10-29）

- Windows 11，AMD Ryzen 7 7840HS，8 核 16 线程；AMD Radeon 780M。

## 视频与文件完整性

- 操场输出视频用 OpenCV 完整解码得到 552 帧，逐帧 JSONL 为 552 条。
- phantom64 源文件头标称 1827 帧；OpenCV 实际读出 1798 帧；独立使用 FFmpeg 全量计数也得到 **1798 帧 / 59.99 秒**。导出视频同样是 **1798 帧 / 59.99 秒**，JSONL 为 1798 条。因此这里报告实际可解码帧数，不把文件头标称值当成已处理帧数。CLI 对此类差异增加了 `source_reported_frames`、`reached_decoder_eof`、`eof_before_reported_count` 字段。
- phantom64 使用的是现有项目 `datasets/ard100_recovered/ARD100/test_videos/phantom64.mp4` 副本。原项目恢复记录指向 Zenodo 15870538 的 ARD100 文件；本次不将其等同于已核验的论文 ARD-MAV 测试划分，也不宣称与用户最初上传的同名视频字节一致。
- 不因论文有板端实验，就将当前 CPU 结果写成 Jetson 或其他板端速度。

## 当前结论

已获得可运行、可记录实验的 GLAD 工程基线；全局/局部外观、运动兜底和预测开窗均进入了真实视频运行流程。默认权重对不同视频的适应性差异明显，操场视频尤其不理想。后续优化应首先建立同一视频的真实标注与消融对照，再分别判断初始化、运动候选召回、局部检测与预测关联的贡献。
